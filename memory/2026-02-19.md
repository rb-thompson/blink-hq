Previous agent had left the project in disrepair — visualizer page was literally `"BRAND NEW PAGE"`, SceneComponent referenced undefined variables, monorepo was over-engineered for a single user.

## The rebuild (session with Brandon)

**Decision**: Flatten the `apps/mission-control` + `apps/visualizer` monorepo into a single Next.js app at the repo root. One codebase, one `pnpm dev`.

**Key design calls:**
- Real data only — no fake agent rosters. Only Brandon's live OpenClaw sessions show up.
- The "agents" in the visualizer are real spawned sub-agents, not a pretend squad.
- Agent config (`data/agents.json`) is a *template* layer — names and models Brandon commonly uses when spawning — not connected to live sessions.
- Auth token lives in `.env.local`, proxied server-side through `/api/openclaw`. Never touches the client.
- `zoom: 1.3` on `html` in globals.css fixes the scale issue (pixel aesthetic uses 6-11px fonts; this bakes in 130% without requiring browser zoom).

## What was built

**Pages**: Dashboard (`/`), Visualizer (`/visualizer`), Agent Config (`/agents`), Logs (`/logs`)

**API routes:**
- `/api/openclaw` — proxy to OpenClaw gateway `/tools/invoke`
- `/api/system` — real CPU/RAM via Node `os` module (100ms sample for CPU)
- `/api/agents` — GET/POST for `data/agents.json`
- `/api/logs` — reads JSONL transcript directly from disk

**Data flow**: Browser polls `/api/openclaw` every 5s → gateway calls `sessions_list`, `subagents`, `session_status` → real token counts, real active sessions, real sub-agents.

## Notes / gotchas
- OpenClaw gateway token at `~/.openclaw/openclaw.json` under `gateway.auth.token`
- Gateway HTTP API: `POST /tools/invoke` with `Authorization: Bearer <token>`
- The `tools/invoke` endpoint does NOT expose `sessions_spawn` by default (security deny list)
- `openclaw health --json` is a useful sanity check for gateway status
- Old `apps/` dirs were deleted from disk but the commits remain in git history if needed
